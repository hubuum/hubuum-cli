Color Themes¶

Hubuum CLI colors are role based. A theme maps structural roles such as key, table_header, title, border, and message, and classified field values, to terminal colors. Classification happens during text rendering, after pipeline transforms; JSON, JSONL, CSV, and TSV retain their original data without styling.

Bundled public palettes are limited to MIT licensed, or clearly MIT-compatible, sources. The current bundled external palettes are:

  • Catppuccin Mocha and Latte, from Catppuccin under the MIT license.
  • Solarized Dark and Light, from Solarized under the MIT license.

First-party themes are distributed under this project's MIT license.

The single-color families keep errors red and warnings yellow. Their remaining roles progress from dark table bands through muted mid-tones to saturated commands and lighter bold headings, so the chosen color remains recognizable without obscuring semantic status.

Selecting Themes¶

List available themes:

hubuum-cli theme list

Preview a theme without changing config:

hubuum-cli theme preview catppuccin-mocha

The preview includes structural roles, sample value classifications, and a dense table with alternating row bands. The selected theme's table_band role controls the shaded rows, independently of the active theme and the configured table style. Normal command output applies that role only to dense tables when output.table_bands is auto or always.

Persist a theme and reload the current REPL session:

theme use solarized-dark

You can also select themes with config, environment, or startup flags:

hubuum-cli --theme hubuum-dark
HUBUUM_CLI__OUTPUT__THEME=catppuccin-mocha hubuum-cli
config set --key output.theme --value solarized-dark

--color never still disables all ANSI styling regardless of the selected theme.

File redirects use the same color mode. auto treats files as non-terminals and strips ANSI styling, never also strips it, and always preserves styling codes in the file.

Editing Colors From the CLI¶

Use theme set ROLE to change a structural role or value category in the active theme. Preview the proposed change, then run it without --preview to save:

theme set url --fg teal --bg none --preview
theme set url --fg teal --bg none
theme set key --fg ansi:bright-cyan
theme set table_header --fg '#e879f9' --bg ansi256:235
theme set network --fg '#38bdf8'

--preview displays the proposed theme without writing configuration, changing the active theme, or syncing preferences. Add --output json to inspect the proposed theme and the edited role's effective style. Both previewing and saving work without a server connection. In an authenticated REPL, saving also follows the existing settings.store_on_server preference-sync setting.

The role can also be supplied as --role ROLE. Role names are the lowercase names in the tables below, including key, table_header, title, message, url, ipv4, cidr, mac, and null_like. The shared network role controls IP addresses, CIDRs, and MAC addresses unless they have individual overrides. This command edits styles; classifier enablement and command prefixes remain custom theme file settings.

Supply at least one of --fg or --bg. Colors accept #rrggbb, ansi:<name>, ansi256:<0-255>, bare ANSI names such as cyan or bright-red, and teal (#008080). For either option, none and default mean the terminal's default foreground or no background. They explicitly clear the channel; they do not restore inheritance. Omitted options preserve the existing channel, and edits preserve bold and dimmed effects.

Overrides are saved in the normal CLI configuration under output.theme_overrides.<theme>.<role> and reloaded immediately. They apply to the named theme, so switching themes retains each theme's own edits. Bundled definitions and custom theme files are left intact. For example:

[output.theme_overrides.rose-pink.url]
fg = "#008080"
bg = "default"

Remove that role's table from the configuration to restore its theme-file or palette defaults. config unset --key output.theme_overrides removes all saved color overrides.

Custom Theme Files¶

Set output.theme_file or pass --theme-file to load additional local themes. Custom theme files are TOML and may inherit from a built-in or another custom theme.

[[theme]]
name = "night-ops"
display_name = "Night Ops"
inherits = "hubuum-dark"

[theme.roles]
command = { fg = "#7ee787" }
heading = { fg = "ansi:cyan", bold = true }
table_band = { bg = "ansi256:235" }

Valid color forms are:

  • #rrggbb
  • ansi:<name>, such as ansi:green or ansi:bright-cyan
  • ansi256:<0-255>

Custom theme names must use lowercase letters, numbers, and dashes. Role styles accept fg, bg, bold, and dimmed. Both effects default to false in explicit role overrides; for example, null_like = { dimmed = true } dims null and empty values using the terminal's normal foreground.

Structural Roles¶

The renderer assigns these roles based on the element's purpose, independently of its text. A header named true remains a header; a message containing 42 remains a message.

Role Used for Default
key Detail field names, including nested keys heading
table_header Table column headers heading
title Help titles, section headings, preview titles heading
border Table borders and dense-table separators muted
message Semantic confirmation and empty-result messages Normal text
table_band Alternating dense-table row backgrounds Palette background
error, warning Error and warning messages Palette status colors
prompt Interactive prompt Palette prompt color
heading Shared default for keys, headers, and titles Palette heading color
muted Explicit muted presentation and null-like defaults Palette muted color

Existing theme files continue to work. Defaults follow overrides: changing heading updates keys, table headers, and titles unless those roles have explicit overrides. theme show NAME lists the effective style for every role and the classifier settings.

Value Classifiers¶

There are twelve categories. Classification uses the entire trimmed scalar value; it does not highlight matching substrings within ordinary text. Boolean and null-like matching ignores ASCII case. Classification does not rewrite the value or change its semantic type.

Category / role Recognizes Default style
number Signed integers, decimals, scientific notation, e.g. -42, .5, 6.02e23 Prompt foreground, without bold
ipv4 Valid IPv4 addresses, e.g. 192.168.0.1 network
ipv6 Valid IPv6 addresses, e.g. 2001:db8::1 network
boolean_true true number
boolean_false false number
null_like null, none, nil, n/a muted with terminal dimming
command Configured command prefix followed by whitespace or end of text Palette command/success color
cidr IPv4/prefix 0–32 or IPv6/prefix 0–128, e.g. 192.168.0.1/24, 2001:db8::/32 network
date Valid YYYY-MM-DD dates, RFC3339 timestamps, and YYYY-MM-DDTHH:MM:SS[.fraction] timestamps without a timezone number
url Absolute URLs with :// and a host, plus file:/// URLs command
mac Six hexadecimal octets with colons/dashes, or three dotted groups of four digits network
Ordinary / value Everything else, including empty text Normal text; empty/whitespace values use null_like styling

All bundled themes use their base accent for network values. The shared network role takes the theme's command foreground without bold, keeping IPv4, IPv6, networks in CIDR notation, and MAC addresses in the theme's color family. Override network to change them together, or override individual roles separately.

Null-like, empty, and whitespace-only values default to muted coloring plus the terminal's dim effect in every theme. Empty text is still classified as ordinary; the renderer applies its null-like presentation afterward. Blank cells remain blank, without introducing placeholder text. Custom null_like overrides can set dimmed explicitly.

Recognition order is booleans, null-like, numbers, IP addresses, CIDRs, dates, URLs, MAC addresses, then commands. The first match wins. CIDRs may include host bits. MAC examples are 00:1a:2b:3c:4d:5e, 00-1a-2b-3c-4d-5e, and 001a.2b3c.4d5e. A twelve-digit string is a number, not a MAC address.

There are no classifiers for hostnames or units such as 10 MB. Ambiguous dates such as 01/02/2026, bare URLs without a scheme, mailto: addresses, and malformed values remain ordinary text. Numbers use decimal syntax, excluding NaN, infinity, hexadecimal, and digit separators. Timezone-free timestamps such as 2020-07-30T11:46:02 use the date style without assuming or converting a timezone. Existing blank rendering of missing/null table and top-level detail cells is preserved; a visible null is classified as null-like.

muted is a presentation role applied after classification, not a value category. Each category can have its own style, including separate true/false styles. An empty style such as ipv6 = {} selects normal text for that category. Dense-table bands combine with value styles; an explicit value background takes precedence over the band background. Wrapping retains the original field's classification on every displayed line.

Values Inside Lists¶

Inline JSON lists classify each scalar item individually, including scalar values in nested lists or objects. For example, both addresses in ["129.240.222.179","192.168.50.193"] use the network color. This also applies to address, broadcast, netmask, and network lists in flattened facts.

Brackets, commas, quotes, whitespace, and object keys stay neutral. The renderer preserves the original JSON text, including escaped strings and numeric notation; it decodes string contents only for classification. Category overrides and disabled classifiers apply to list items. Invalid JSON lists remain ordinary text.

Detail fields, extracted values, and table cells share this behavior. Wrapped items retain their classification, and dense-table row bands remain intact. JSON, JSONL, CSV, and TSV output keeps the original values without added styling.

Tuning Classification and Styles¶

Configure classifiers alongside role overrides in a custom theme:

[[theme]]
name = "network-ops"
inherits = "hubuum-dark"

[theme.roles]
key = { fg = "ansi:cyan" }
table_header = { fg = "ansi:cyan", bold = true }
title = { fg = "ansi:green", bold = true }
border = { fg = "ansi:bright-black" }
message = { fg = "ansi:green" }
number = { fg = "ansi:cyan" }
network = { fg = "ansi:green" }
null_like = { fg = "ansi:bright-black", dimmed = true }
boolean_false = { fg = "ansi:yellow" }
cidr = { fg = "ansi:magenta" }
url = { fg = "ansi:blue" }
value = {}

[theme.classifiers]
disabled = ["date"]
command_prefixes = ["hubuum-cli", "osp"]

By default all classifiers are enabled and the command prefix is hubuum-cli. Prefix matching is case-sensitive and requires whitespace or the end of the value after the prefix, so hubuum-client is ordinary text. Prefixes must be nonempty, trimmed, and free of control characters. An empty prefix list disables command recognition.

disabled accepts category names from the table (ordinary names the fallback category). A disabled category falls back to ordinary styling without trying another classifier. Unknown names, including muted, are rejected.

Child themes inherit classifier settings when they omit [theme.classifiers]. Providing that table replaces the inherited settings; omitted fields then use their defaults. Role overrides inherit individually. Changing number updates numbers, booleans, and dates that still use its default style. Changing network updates IP addresses, CIDRs, and MACs that still use its default style.
