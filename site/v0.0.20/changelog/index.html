Changelog¶

[Unreleased]¶

[0.0.20] - 2026-10-24¶

Added¶

  • Filter object list by related objects with repeatable --related ALIAS=CLASS or --related-id ALIAS=ID, --related-depth ALIAS=DEPTH, and --related-where ALIAS.FIELD OP VALUE. Support up to four groups, depth 1–10, ordinary pagination, computed output and sorting, pipelines, and REPL completion.
  • Add local typed string predicates CONTAINS, ICONTAINS, STARTS_WITH, ENDS_WITH, IEQUALS, and opt-in FUZZY, including negated forms. Existing regex filters retain their syntax and meaning.
  • Add relative datetime operands now and now-Ns/m/h/d with one clock sample per pipeline application and an injectable library clock.
  • Add optional selector diagnostics through CHECK STRICT / CHECK ALLOW and PipelineSettings, with available paths and spelling suggestions.
  • Add P ROWS for projection aligned by original array-member addresses and U selector AS item for unrolling into a named field without promoting members.
  • Add offline H / HELP [verb|topic|CURRENT] to explain options and the current statement without executing its command. The existing help pipe topics use the same reference; help and diagnostic options support REPL completion.

Fixed¶

  • Reject related-object JSON paths with empty segments, including doubled dots immediately after data or json_data, instead of silently changing the path.
  • Preserve large integers in numeric casts, comparisons, sorting, distinct, and representable integer sums. Reuse compiled regexes and cast literals across rows and pipeline applications.
  • Resolve projection removals against original addresses before compacting arrays, and share quote/escape handling across pipeline, predicate, comma-list, completion, and redirect scanning.
  • Count each input row once per distinct group-key combination, even when an array repeats a key. Reject unroll field collisions instead of silently overwriting parent values.
  • Preserve structured response data through pipelines for version and config paths, preference and alias updates, theme previews, issued tokens, task output and submission, computed previews and mutations, class/group details, and relation graphs. Mutation confirmations expose a semantic message.
  • Render legacy JSON responses through the shared pipeline and final renderer. Exclude auxiliary text from structured payloads while retaining it in JSON debug messages. Theme previews now honor structured output formats.
  • Preserve object details and historical context in JSONL, CSV, and TSV views. Count empty search results as zero records instead of counting status text.
  • Replace obsolete --limit 0 empty-result examples with a valid unmatched name filter; page sizes must be positive.
  • Apply pipelines consistently to offline commands, including configuration and theme inspection, through the shared catalog command handler.
  • Validate task IDs, page sizes, computed-field revisions and patches, export scopes, remote-call subjects, and history timestamps before resource lookup.
  • Enforce semantic output and extension failure validation during direct JSON deserialization as well as through protocol parsing.

Changed¶

  • Upgrade published hubuum_client from 0.17.0 to 0.19.0 and adapt to validated resource IDs and computed revisions. Breaking validation: zero and negative resource IDs now fail locally, including IDs in deserialized server responses. Replace invalid or sentinel IDs in scripts and fixtures with real positive IDs. Computation revision zero remains valid. The server v0.0.20 target, pinned image, OpenAPI routes, blocking-only client features, MSRV declarations, backup formats, and saved-session formats are unchanged; no server or cache migration is needed.
  • Breaking filter behavior: integer-only sums now serialize as integers; consumers requiring floating-point values must convert them explicitly. Array exclusions in a single P stage use original indexes; use separate stages for sequential removals. Repeated group keys no longer multiply member counts; use U tags AS tag | G tag | C to count occurrences. Unroll collisions now fail; migrate to U selector AS item and select fields under item.
  • Breaking DSL/API additions: H, HELP, and CHECK are reserved stage words; search for them with F H, F HELP, or F CHECK. Quote a field named ROWS after P to distinguish it from P ROWS. Library callers matching PipeStage, PredicateOperator, or TypedLiteral exhaustively must handle the added variants. New local text/time predicates are rejected by server search with guidance to use a local pipeline.
  • Add strsim 0.11.1 as a direct hubuum-filter dependency for fuzzy matching and selector suggestions; this version was already in the workspace lockfile. This filtering change does not alter the declared Hubuum server target, OpenAPI surface, or MSRV.
  • Breaking pipeline changes: commands with custom text responses now expose their JSON fields to pipelines. Replace filters on rendered labels with field selectors such as VALUE cli_version, VALUE token, or VALUE message. Composite class/group details, relation graphs, and shared computed lists and mutations provide one complete response document; use nested selectors such as class.name, group.groupname, objects, relations, definitions, or state. Ordinary list-table selectors and unpiped text/JSON response shapes remain unchanged, except that theme preview --output json now returns the theme definition. See output pipelines.
  • Breaking validation changes: history --at rejects pagination/sort flags; named export templates reject ad-hoc relation options; remote calls reject selectors unrelated to their subject; related-export specifications reject extra colon-separated segments. Remove the inapplicable options from scripts. Task IDs and page sizes must be positive, computed updates must include a change, and extension responses must satisfy their documented output and failure invariants. Valid template exports retain the legacy --scope syntax.

[0.0.19] - 2026-10-23¶

Added¶

  • Add relation object graph --data to include object data in JSON graph output without additional object lookups.
  • Inspect or end an existing rotating session with auth status and auth logout without creating a new login. Status omits credentials; logout clears only its matching saved session family.
  • Add history timelines, exact historical object-name lookup, as-of object populations, direct relationship history, and historical shared computed values. Preserve retained-history coverage, unavailable endpoint context, and pagination metadata in JSON and pipelines.
  • Add me token activity, user token activity, and service-account token activity with offset pagination and complete issuance, source, retention, and overflow evidence.
  • Add object hydrate for bounded paths to a target class and admin query-observations show|enable|disable for the shared runtime override.
  • Accept and display directional class-relation labels, preserving their meaning when class IDs are reordered. Include session and credential-activity settings in admin config.
  • Disable persistent password-session storage with --session-storage none or server.session_storage = "none". Rotate credentials only in memory, ignore saved sessions and legacy token caches, and leave existing credentials intact.
  • Opt into macOS Keychain or Linux Secret Service for rotating login sessions with --session-storage keychain or server.session_storage = "keychain". File storage remains the default. Existing matching sessions move to the keychain only after a successful secure write; keychain errors never fall back to file credentials. Add the platform-specific keyring credential-store crates.

Security¶

  • Restore owner-only permissions on existing session caches and lock files before use, including caches restored or copied with broader permissions.

Fixed¶

  • Fix Linux ARM64 static binary linking with native keychain support, keeping release archives self-contained.
  • Fetch hubuum-room placement and object data in one depth-two graph after resolving the Room, replacing per-Jack relation and per-Host object lookups. Breaking for wrapper-only upgrades: upgrade hubuum-cli together with the wrapper; it now requires relation object graph --data support.
  • Keep object-relation class labels aligned with their objects when object IDs and class IDs have different endpoint orderings.
  • Fetch history show --id directly instead of scanning a bounded history list. Accept numeric class/object selectors so retained history remains accessible after deletion. History tables show history IDs, revisions, operations, and validity intervals while existing JSON snapshots retain their fields.
  • Honor positional object names after history class selectors and positional token IDs after credential-owner options. Suppress activity pagination hints for summary pipelines while retaining warnings about partial evidence.
  • Coordinate concurrent cache-miss logins so processes starting with empty or expired caches reuse one session instead of replacing each other's credentials. Recheck storage after password entry under a cross-process login lock.
  • Restore remembered password logins across CLI restarts and wrapper subprocesses. Save rotating sessions in sessions.json, isolate server/provider/user identities, and coordinate refresh across processes with an exclusive lock and atomic writes. Passwords are never stored. Expired, revoked, or uncertain sessions require login.

Changed¶

  • Upgrade published hubuum_client from 0.16.0 to 0.17.0. The Hubuum server v0.0.20 target, pinned server image, blocking-only client features, and backup format 10 remain unchanged. No cache migration is required.
  • Move persistent session storage into the hubuum-session workspace crate, retaining cache formats, keychain identifiers, and process coordination. The crate declares Rust 1.89 for filesystem locking; the CLI still has no declared MSRV.

[0.0.18] - 2026-10-22¶

Changed¶

  • Breaking server target: pin published Rust SDK 0.16.0 and require Hubuum server v0.0.20. Password login and provider discovery use /api/v1/auth. Upgrade server API, workers, and restore executors together during the offline migration, retain a pre-upgrade snapshot, and sign in again.
  • Breaking credential cache behavior: new interactive sessions stay in memory and rotate automatically. Each new CLI process needs credentials; use an explicit PAT/service-token file for automation or the REPL for reuse. Existing cache entries can still be read and validated; no refresh credential is persisted across processes.
  • Recognize backup format 10 and restore formats 6–10. Older servers cannot restore format 10; use a matching upgraded restore executor.
  • Refresh direct/transitive dependencies and GitHub Actions, including jaq-all 0.4. Adapt the embedded jq runner to its input-filename API.
  • Treat SDK session expiry as an authentication failure in interactive recovery. Read-only commands can retry once after sign-in; mutations are not replayed.

Security¶

  • Update rustls-webpki to 0.103.16 and webpki-roots/webpki-root-certs to 1.0.10 to reject distrusted emSign certificate chains (RUSTSEC-2026-0382, RUSTSEC-2026-0381, and RUSTSEC-2026-0383).

Fixed¶

  • Reuse the class schema fetched by object list when choosing automatic data columns, avoiding a second class lookup for text and pipeline output.
  • Reuse embedded collection metadata for object details and known class metadata when listing or deleting class relations. Same-class relations avoid duplicate class and object lookups.

[0.0.17] - 2026-10-19¶

Added¶

  • Include versioned, structured command diagnostics in JSON output when --debug is enabled: elapsed milliseconds, API/HTTP/custom transport counts, and nested span timings, outcomes, statuses, routes, retries, and pagination details. Direct commands, scripts, the REPL, pipelines, and file redirects share this behavior. JSON warnings and errors are included as arrays in the response.

Changed¶

  • Breaking for JSON debug consumers: --debug --output json now returns {"data": ..., "debug": ...} instead of a raw result with a text debug report on stderr. Read the original result from .data and diagnostics from .debug. JSON timing ends before final response serialization and writing. JSON output without debug and diagnostic reports for other output formats are unchanged.

[0.0.16] - 2026-10-19¶

Added¶

  • Add shared --debug diagnostics for command duration and each client-library API operation, including its duration and success or failure. Reports use command-scoped tracing spans, show execution and rendering time, and collect client-library requests, HTTP attempts, retries, pagination, and stream spans. HTTP attempts include status codes and are counted separately from client calls. Reports go to stderr and work with direct commands, scripts, the REPL, and workflows.

Changed¶

  • Declare tracing 0.1 as a direct dependency for command diagnostics, using the version already present in the lockfile. Upgrade the pinned client from 0.15.0 to 0.15.1 for its versioned diagnostics contract; the declared server target remains v0.0.19.
  • Breaking for extension authors: debug is now a reserved host option. Rename any extension option named debug or using the --debug alias before upgrading. The flag controls host diagnostics and is not forwarded to executable extensions.

Fixed¶

  • Fit grouped table headers into the space available for each column, keeping dotted paths on one line when possible and wrapping between path segments when needed instead of always stacking every segment.

[0.0.15] - 2026-10-19¶

Added¶

  • Add administrator event sink preview and test commands using an audit event UUID and subscription ID. Preview renders without delivery; test queues a real message and bypasses enabled flags and subscription filters. Test submissions are never replayed automatically after ambiguous failures.
  • Add event subscription list|show|create|update|delete --system, with explicit collection/system scope selection, authentication subject filters, and REPL completion. System lists return all subscriptions; use local pipelines for filtering and sorting.

  • Add audit resource --include-relations for class and object relationship activity, including deleted relations, while retaining entity-only defaults.

  • Manage class query-usage declarations with class query-usage list|create|replace|delete|analyze. Replacement and deletion require an explicit reviewed revision. Analysis reports workload evidence, schema compatibility, suggestions, native resource ownership and adapter progress without adopting suggestions or preparing indexes. See query usage.

  • Stream structured searches with search --target ... --stream or search --query-file ... --stream. Text results and JSONL event envelopes arrive incrementally; JSON, pipelines, and redirects retain complete output. Truncated streams and terminal errors fail without replaying partial results.

  • Add self_update.check_on_startup (default false) to optionally announce newer stable releases when the interactive shell starts, without installing them. Add self_update.enabled (default true) so managed installations can disable all update checks and self-update installation. Both settings support TOML configuration, environment variables, and the config commands. These local settings can be changed without connecting to a Hubuum server.

  • Add a positive --limit override to class/object show and relation graph commands. Omit it to retain the server's configured graph size limit.

  • Add the standalone hubuum-room wrapper, which lists Room and Jack comments and connected Hosts' IP addresses, names, and CPUs in the style of miami_room. It accepts a Room name or object ID and supports structured output with --json. Room names may omit an initial B when no name or ID matches directly.

Changed¶

  • Use the client's typed structured-search requests, responses, and SSE decoder. Structured resource timestamps now use the client's equivalent UTC +00:00 representation. Terminal predicates, cursor continuation, and local resource pipelines remain supported.

  • Breaking (server target): pin hubuum_client 0.15.0 and target the released Hubuum server v0.0.19 image. Upgrade matching server processes, replace blank principal names before upgrading, and retain a pre-upgrade snapshot and matching binaries for rollback. Direct server connections require HTTP/1.1. The client retains its blocking feature and Rust 1.88 MSRV; the CLI declares no MSRV. The upstream contract grows from 235 to 240 operations.

  • Breaking (backup output): new server backups use format 9 and preserve query-usage declarations. Upgrade the restore server before using new backups. Restore staging continues accepting formats 6, 7, and 8 alongside format 9; older artifacts need no conversion.

  • Shortened installation guidance, pinned the shared Atlas walkthrough, and fixed the extension tutorial’s upgrade step.

  • Update the TOML dependency from 1.1.6 to 1.1.8, including fixes for key serialization and duplicate-key detection when deserializing tables.
  • Refresh Rust dependencies, including JSONPath 1.0.12, self-update 1.3.1, Serde JSON 1.0.154, Tokio 1.53.3, SHA-2 0.11.1, Syn 3.0.9, and ZIP 9.0.5 for updater tests. Refresh pinned GitHub Actions, shared documentation tooling, Markdown lint, the Rust 1.99.1 Alpine builder, and the PostgreSQL 18 fixture. The client/server upgrade and its migration requirements are described above.

Fixed¶

  • Fixed explicit file:///C:/... value sources on Windows, including paths with spaces. File and URL loading remains restricted to options that opt into value sources.

  • Check self-update installation directory access before downloading, including when the existing executable is writable but its directory is not. Errors give the target path and package-manager or administrator guidance. Availability checks still work without a writable installation directory. The updater now uses the existing tempfile dependency at runtime for this access probe.

  • Keep object show --data --path output as sorted, flattened key/value rows, including nested fields under the selected path, instead of embedding JSON objects in the text output. Keep distinct values when flattened keys collide and preserve selected values with no flattened fields. Explicit --json output remains available.
  • Add help jsonpath with syntax, shell quoting, and examples for nested fields and arrays. Object command help links to this topic; invalid paths now include examples and the help reference alongside the parser error.
  • Correct missing JSONPath roots when adding $ or $. produces a valid path, with a warning showing the original and corrected expression.
  • Honor object show --output json consistently with --json.

[0.0.14] - 2026-10-06¶

Added¶

  • Manage collection-owned webhooks with event sink list|show|create|update|delete --collection NAME, including chat presets with --destination-url-file PATH. Subscription sink lookup and completion use collection-scoped discovery.
  • Administrator commands event sink grant, revoke, and collections manage direct collection grants for shared sinks through the Rust client.

Fixed¶

  • Collection destination filters and sorts match the server's searchable metadata.
  • Breaking (preset arguments): chat presets read credential-bearing URLs with --destination-url-file PATH; literal destination URLs are no longer accepted as preset arguments. Tokenizer trace logs record token counts rather than argument contents.

Changed¶

  • Refresh compatible Rust dependencies, including Hyper 1.12, h2 0.4.20, Jiff 0.2.38, and Zeroize 1.9.1.
  • Breaking (backup output): Hubuum v0.0.18 writes format 8; restore accepts formats 6, 7, and 8. Older servers cannot restore format 8. Keep older artifacts for recovery and upgrade all server processes before taking new backups.

  • Breaking (server target): target Hubuum v0.0.18 through the exact published hubuum_client 0.14.1 dependency. Stop all writers and take a PostgreSQL snapshot before the collection-sink migration. Start matching v0.0.18 binaries; rollback requires that snapshot and v0.0.17 binaries. See upgrade instructions.

  • Collection self-service requires the server v0.0.18, and both ManageEventSubscription and ReadAudit. Existing administrator subscription workflows retain v0.0.17 support; only a missing scoped discovery route permits the legacy lookup. Permission denials never trigger that fallback. The CLI now depends on Rust client 0.14.1; publish that client before publishing this CLI update.

Changed¶

  • Document compatibility through the pinned client library, generic webhook setup, and equivalent full commands for the Slack, Mattermost, and Discord presets. CLI help includes the generic webhook setup path.
  • Pin hubuum_client 0.13.0, which targets Hubuum server v0.0.17, and use its immutable server image for CLI integration checks. Verification uses Rust 1.99. See pinned integration evidence.
  • Refresh direct and transitive Rust dependencies, including Reedline 0.52.1, JSONC parser 0.34.0, Tokio 1.53.2, and TLS dependencies. Extension manifests retain the same JSONC syntax. Update the pinned Rust toolchain action, shared documentation workflow revision, Rust 1.99 builder, and PostgreSQL 18 fixture. All other Action pins were checked against their current upstream releases.
  • Breaking (backup output): server v0.0.17 creates format 7 backups, which older servers cannot restore. CLI restore staging now accepts both 6 and 7; existing format 6 backups need no conversion. Keep older backups for recovery on older servers. Restore resets transient sink scheduling while retaining notification configuration and terminal delivery history.
  • Breaking (server upgrade): stop all API, worker, and restore-executor writers and take a PostgreSQL snapshot before applying the notification migration. Deploy matching v0.0.17 binaries together. Binary-only rollback is unsupported; restore the snapshot with matching v0.0.16 binaries to recover, losing later writes. Optional Treetop backends require protocol 0.1 and migrated policy bundles. See upgrade instructions.

  • Breaking (delivery health output): system subscriptions have nullable collection IDs. Structured consumers must accept collection_id: null.

  • Reduce HTTP requests for object show by reusing the root object returned in the relation graph and resolving collection names together. Object lists, class details, search, and relation output also reuse available class and collection metadata. Text, JSON, pipeline output, and computed fields retain their content.

  • Documentation uses the shared warm Hubuum theme from the ecosystem site's unversioned stylesheet, including retained release editions. Future styling updates no longer require changes or rebuilds in this repository.

Added¶

  • In-place binary updates with self-update and a metadata-only --check, available in the CLI and REPL without Hubuum login. The new hubuum-update workspace crate uses self_update 1.3 with Rustls, tar/ZIP extraction, and mandatory published SHA-256 verification. Updates use the exact platform archive from a strictly newer stable release; restart the CLI afterward. See installation and platform details.
  • Chat webhook setup with event sink create --target slack|mattermost|discord and --url-secret-ref: normal webhook configuration with provider templates, acknowledgements, retry/cooldown rules, and one-second pacing. REPL completion, command help, and a setup guide cover secret storage and Discord's required wait=true URL option. Discord messages disable mentions.

  • --delivery-policy JSON on sink creation and updates; {} clears configured pacing. Subscription --filter accepts task_kinds through the updated client. System-subscription CRUD and notification preview/test remain server API operations without dedicated CLI commands.

  • A walkthrough using the shared Atlas example inventory, with classes, objects, relations, and permissions linked to the server-owned import and backup.

  • A searchable, versioned documentation site with shared Hubuum navigation, automatic GitHub Pages publishing, the latest release as its default, immutable release snapshots, and an explicit development edition.

Fixed¶

  • Documentation tables keep long environment-variable names readable, use wider reference layouts, and scroll within the table on small screens. Shared style fixes also reach retained release documentation.

  • Preserve local filters and projections when continuing structured search with next. Reject excessive boolean expressions regardless of keyword casing before recursive parsing, preventing stack overflows from long lowercase or mixed-case negation chains.

Approval failures and ambiguous mutation responses are not replayed; inspect the reported ID with auth approval show ID before retrying. See credential migration.
  • Breaking (import payloads): submission preserves the full supported graph, including credential and integration entries, instead of dropping extended fields. Review existing import files before resubmission: previously ignored entries now take effect.

  • Add typed task list --where FIELD equals VALUE discovery filters and comma-separated kind/status sets. task show exposes retained targets, options, output availability, remote side effects, and schema/rebuild details when present. See task discovery.

  • Refresh the pinned PostgreSQL 18 integration fixture image.

  • Refresh locked Rust dependencies, including Clap 4.6.7 and Quinn 0.11.12, and update Docker build workflow actions and the pinned Rust builder to 1.98.1.

  • Resolve collection names in class show when the server returns only a collection ID. Related object and class queries now accept class and collection names through --where class equals Hosts and --where collection equals Inventory.

  • Include server v0.0.15 schema evolution and task cancellation in the v0.0.16 upgrade. Update locked Rustls to 0.23.45. Administrative output includes schema budgets, backup row limits, and task execution timeouts.

  • Breaking (schema commands): remove --schema/-s and --validate/-v from class create and class modify. Use class schema stage, impact, and activate for all schema policy changes, including initial setup. Activation requires an explicit expected active revision and defaults to rejecting incompatible objects. Add revision inspection/abandonment, compliance pages, revalidation, work diagnostics, and retained HTML reports. See schema migration examples.
  • Add a schema-scope help walkthrough and allow class schema stage --validate to reuse the active schema. Preview validation changes with impact analysis before explicit activation; --schema null still explicitly removes a schema. stage --from-revision copies a previous policy into a new proposal for impact analysis and activation, with an optional validation override.
  • Schema commands now show concise text summaries by default, including impact readiness, counts, and bounded failure groups. Aligned labels follow the configured output padding; results, impact, and failure details are grouped and indented, with zero-only secondary counters omitted. Full schemas and diagnostics remain available through --output json, structured formats, and pipelines.
  • Complete recent schema task IDs with status/summary labels for work, reports, cancellation, and activation. Suggestions use a bounded task-list request, without downloading diagnostics; task cancellation also gains ID completion.
  • Add task cancel with validated reasons and optional expected status, plus class-scoped class schema cancel. Cancellation can remain pending while executors finish cleanup; inspect task show for cancellation metadata, deadlines, unattempted items, terminal reasons, and remote side effects. Task filtering/completion includes schema_validation.

  • Breaking (server and backup compatibility): backups now require format 6. Restore format 5 artifacts with the matching older server, migrate, then create new format 6 backups; no conversion is available. Drain old workers, run migrations in a quiet window, and upgrade server, administrator, template worker, and restore executor together. [0.0.10] - 2026-08-30¶

  • Added canonical class fields --name <class> field discovery, with object fields --class <class> retained as a deprecated compatibility alias that prints an exact replacement command. Existing invocations continue to work; users should migrate to class fields --name <class>. Reusable command deprecation metadata now annotates help and rewrites renamed options in warnings. The inventory includes enabled shared and personal computed selectors alongside sampled data.* paths, identifies each field's source, and summarizes computed values observed in the same object sample. This is a breaking output-shape change: the inventory gains a Source column and computed-selector rows. Structured consumers that assumed an exact column set or data-only rows must accept the new column and rows.
  • Added extension packs under extension <pack>, with dependency-free portable JSONC/JQ workflow packs as the preferred kind and a versioned argv/JSON protocol for explicitly executable packs. Packs have deterministic system and user discovery, catalog help and static completion, semantic output pipelines, diagnostics, and local user-package lifecycle commands. The Host, Jack, and Room placement example is one portable workflow pack; the Host shell wrappers remain a tested executable pack pilot and retain their standalone entry points. Workflow commands use strict manifest schemas and a catalog contract with stable input IDs, portable types and cardinality, explicit effects, early compatibility checks, and preserved step-output metadata. Manifest commands, options, workflows, and inputs use nested named objects. Workflow steps are tagged objects in ordered arrays, keeping IDs, bindings, conditions, and dependency references together.
  • Expanded the native semantic pipeline with typed boolean F WHERE and reject WHERE predicates, stable multi-key sorting with strict casts and explicit null placement, projection aliases and deep exclusions, stable D/distinct, global aggregation, selector counts, and ordered first and last aggregates. Pipeline stages now operate on canonical semantic JSON before final rendering, validate their selectors, output names, and shape transitions, and apply post-group filters to visible group summaries without mutating member rows. These are breaking validation changes: malformed selectors, duplicate or colliding output names, unsupported stage-shape transitions, and invalid values sorted with AS ip now fail instead of being tolerated or coerced. Users must correct selector syntax, give projected/grouped/aggregate outputs unique names, reorder incompatible stages, and filter invalid addresses or select a non-IP cast. Existing legacy filter, projection, one-key sort, and grouped aggregate forms remain available.
  • Interactive REPL sessions now recover from expired or revoked credentials by re-reading token files or logging in again. Read-only commands retry once after successful authentication; potentially mutating commands are not replayed and identify the failed HTTP method and redacted path for review. One-shot commands and scripts remain non-interactive.
  • Server startup now checks the unauthenticated health endpoint before asking for an interactive password. Unconfigured ports are tried in order on 443 and 8080, while an explicitly configured port remains authoritative.
  • Fixed object show relation expansion to exclude same-class roots in the server request when the default same-class filter is active, preventing high-fanout neighbors from hitting the graph-size guard before local filtering. Completion now also offers --class before the class-dependent --name option.
  • Updated hubuum_client to 0.9.1 while retaining the declared Hubuum server v0.0.9 target and its pinned immutable integration image. The client update adds strict JSON-query-path validation, atomic export downloads, expanded OpenAPI model reconciliation, and refreshed dependencies. The complete CLI dependency and release-action set was also refreshed, including the h2 update that addresses RUSTSEC-2026-0258.
